# StripBot → Codex 能力对齐：实施与验收清单

> 状态：实施计划，不代表功能已完成。每项只有经过实际测试才能标记为完成。

## P0 — 安全且可验证的 Agent 执行链路

- [ ] Windows 实机验证 Codex CLI app-server 启动、会话创建、流式事件、文件修改、终端命令和失败恢复。
- [ ] 为每个 Agent 工具调用建立不可绕过的统一授权入口，区分 allow / ask / deny。
- [ ] **修复 MCP 权限绕过**：目前 `modules/integrations/mcp/index.cjs::asMcpServers()` 会把所有已启用 MCP 服务器传给 Codex；本地权限文件的工具级 deny/ask **未被执行引擎强制执行**。在实现 Codex 端工具过滤或受控代理前，不得宣称 deny/ask 已生效。
- [ ] 为 MCP HTTP / stdio 建立真实端到端测试：initialize → initialized → tools/list → tools/call → 模型继续生成。
- [ ] 将审批请求绑定具体会话、工具、参数哈希和单次执行；超时、拒绝、断线、重放一律失败关闭。
- [ ] 测试取消、暂停、队列、同工作区互斥、不同工作区并行、意外退出恢复。
- [ ] 测试命令沙箱及危险操作批准，不通过时不执行。

## P0 — 项目变更与恢复

- [ ] 任务开始前记录 Git HEAD、工作区已修改文件及未跟踪文件，禁止静默覆盖。
- [ ] 生成任务级 diff；提供逐文件审查、选择性恢复、冲突检测。
- [ ] 回滚不得调用无条件 `git reset --hard` 或删除未跟踪文件。
- [ ] 所有写入、回滚及测试操作提供审计记录，过滤密钥。

## P1 — 自主开发闭环

- [ ] 明确规划 / 执行 / 测试 / 修复 / 验收状态。
- [ ] 自动识别项目测试命令，用户授权后执行，限制重试次数。
- [ ] 长任务持久化、崩溃恢复、重复执行防护。
- [ ] 项目索引、规则文件、上下文压缩及多轮任务关联。

## P1 — 扩展与协作

- [ ] MCP、Skills、GitHub、本地工具统一注册与可观测性。
- [ ] 多 Agent 分工、共享任务状态、文件冲突保护。
- [ ] 可选数据库/企业系统连接，采用最小权限、凭据隔离与审计。

## 测试门槛

1. `npm test`：必须实际执行并记录通过/失败数。
2. 前端 TypeScript 编译与打包：必须实际执行。
3. Windows Electron 冒烟测试：必须实际执行。
4. MCP 真实服务器连接及 allow/ask/deny 执行时阻断测试：必须实际执行。
5. Git 回滚及异常恢复测试：必须实际执行。
6. 未测试项标记 **未验证**，不可用“代码已提交”代替验收。

## 实施约束

- 保留现有 UI、主题、桌宠、插件等功能；不修改模型响应速度滑块。
- 修改前检查最新代码与未提交改动；每阶段小提交、可回退。
- 默认最小权限，禁止后台自动运行未知第三方程序。
- 发现权限绕过时，优先封堵再继续功能扩展。
